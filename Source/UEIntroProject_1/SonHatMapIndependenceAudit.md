# SON HAT — map independence and city handoff

Audit of the **current local working tree**, 17 October 2026, branch `integration/son-hat`, base HEAD `4e47b89d03b03a18276cfe4caf55b426f7391a05`. Existing uncommitted work is part of the implementation reviewed here. This report supersedes older integration notes that say Director Z sets the flood height, presentation uses Canvas/debug-only drawing, or recovery should always use world Z 150–200.

## Decision

The reusable gameplay can move to city rooftops through actor placement and configuration. No city/map names or rooftop coordinates occur in the reusable runtime C++ (test fixtures and the deliberate bootstrap harness are separate). **Final city release readiness is PARTIAL:** the saved playable level still has placeholder roofs, city collision/loading has not been verified, startup is still the intro map, and no packaged build was tested. Do not interpret a referenced Level Instance or passing graph tests as proof of a loaded, traversable city.

Confirmed fixes in this pass:

1. Grapple previously required an actor tagged `GrappleAnchor`. Added optional **Allow Solid World Surfaces**, preserving anchor-only defaults and existing swing/reel physics.
2. Rope obstruction previously ignored the entire attachment actor and all other anchor-tagged actors. It now ignores only endpoint contact with the attached **component**, within **Rope Endpoint Tolerance** (12 cm, bounded to 30). Other faces/components on the same building obstruct normally, after the existing grace period.
3. Recovery previously used fixed **Fall Recovery World Z = 200**. Default recovery now triggers after a configurable **1500 cm drop from the last supported ground position**, only while falling. Absolute world Z is an explicit legacy opt-in. A valid CMC walkable floor is required to establish a checkpoint. Recovery uses collision-checked teleport and clears velocity; an obstructed checkpoint logs a warning and is discarded. Replay clears the old checkpoint.
4. Replay previously teleported the pawn without stopping CharacterMovement velocity. Return-to-start replay now stops movement, resets view rotation, checks spawn obstruction, and resets the recovery checkpoint. Failed spawn placement produces Configuration Error.
5. Multiple Directors now produce a clear configuration error rather than competing for local input/HUD/network ownership. Optional **Expected Node Count / Expected Link Count** reject incomplete streamed networks at round start.
6. The opening HUD hint now uses configured duration/budget instead of always claiming 90 seconds / 3 links.

## Scope / limitations

Product source changes are exactly `GrappleComponent.h`, `GrappleComponent.cpp`, `GrappleComponentTests.cpp`, `SonHatEvacuationDirector.h`, `SonHatEvacuationDirector.cpp`, `SonHatEvacuationDirectorTests.cpp`, and this new report. Local verification helpers created: `Saved/MapIndependenceAudit/InspectAssets.py` and `Saved/MapIndependenceAudit/VerifySpatialPIE.py`, plus generated logs/reports, layout selector, original copies and pass-only forward/rollback patches in that ignored evidence folder. Rollback patch passes `git apply --check`; do not apply it over later concurrent changes without reviewing the diff.

Manager, Node, Link, scoring, HUD, PopulationPresenter, Blueprints, materials, maps, builder, configuration, and Jam/B were not edited. Hash comparisons confirm both tested saved maps and BP_JamGameMode/BP_GrappleCharacter are unchanged. Existing uncommitted changes remain.

The final city is not certified ready: there has been no human city playtest, packaged build/cook, performance benchmark, streamed unload/reload recovery, moving-building support, rope wrapping, physical flood, crowd movement, rescue simulation or death simulation. The saved playable level still needs its placeholder placements moved onto measured city geometry. These are configuration/integration and verification tasks, not reasons to rewrite the gameplay systems.
